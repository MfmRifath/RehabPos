# 01 — Overview and vision

> **Disclaimer:** RehabPose is a research and portfolio prototype. It is not a medical device, has not
> been clinically validated, and must not be used to diagnose, treat, or replace advice from a
> qualified healthcare professional. Stop exercising if you feel pain. Thresholds are engineering
> defaults, not clinical prescriptions.

## Problem
Home exercise programmes for upper-limb rehabilitation (after shoulder surgery, frozen shoulder,
stroke and similar) are often done without supervision. Patients cannot easily tell whether they are
reaching the intended range of motion (ROM), moving too fast, or compensating, for example by leaning
the trunk or hiking the shoulder. Therapists rarely see objective data between visits.

## Vision
RehabPose is a coach that needs only a camera. A laptop webcam or phone is enough: no wearables and no
depth sensor. It counts repetitions, measures joint angles, detects common compensations and gives one
clear cue at a time on screen and by voice. Each session becomes a report a therapist can review.
Video never leaves the user's device in live mode. Only 33 pose landmarks per frame are sent to the
local backend.

## Scope (v1)
| Exercise | View | Primary measure | Status |
|---|---|---|---|
| Shoulder flexion | sagittal (side-on) | upper-arm–trunk angle | core |
| Shoulder abduction | frontal | upper-arm–trunk angle (frontal projection) | core |
| Elbow flexion | sagittal (frontal allowed with a warning) | elbow flexion | core |
| Shoulder external rotation | frontal | forearm rotation (world landmarks) | experimental |
| Forward reach | sagittal | wrist forward displacement / arm length | optional |

Full biomechanics in [04_exercise_spec.md](04_exercise_spec.md).

## Primary users
- **Patient**: does prescribed exercises at home and wants simple, trustworthy feedback.
- **Therapist**: sets targets and thresholds per patient and reviews progress and reports.
- **Demo viewer**: a recruiter or engineer trying the live demo for a few minutes.
- **Researcher**: reproduces the pipeline and evaluates models on public and own datasets.

User stories are in [02_srs.md](02_srs.md#4-user-stories).

## Approach in one paragraph
The browser runs MediaPipe Pose Landmarker (Tasks Vision, GPU delegate) on the webcam stream and draws
the skeleton overlay. It sends only the landmarks over a WebSocket to a FastAPI backend. There, a
deterministic core engine processes them in order: One Euro smoothing, then joint angles, then a
hysteresis rep state machine, then YAML-configured form rules (optionally fused with a small temporal
ML model). The result is a feedback message: phase, rep count, flags and at most one cue. Uploaded
videos go through the same engine offline, using Python MediaPipe. Details are in
[03_architecture.md](03_architecture.md).

## Non-goals
- Clinical diagnosis, prescription or any claim of clinical validity.
- Lower-limb, gait or full-body exercises (v1 is upper limb only).
- Cloud hosting, accounts, or multi-tenant deployment. The app runs locally or in a single Docker container.
- Using CUDA/NVIDIA hardware. The target platform is Apple Silicon (MPS/CPU); Linux is CPU-only.

## Assumptions
1. The user can stand or sit so that the head, both shoulders, elbows, wrists and hips are visible.
2. Camera placement roughly matches the exercise view (side-on for sagittal, facing for frontal).
3. Monocular 2D landmarks are accurate enough for coaching-grade angles in the intended view. We
   verify this against manual angle annotations; the targets are below.
4. All default thresholds are engineering defaults derived from the project spec. They are not
   clinical values, and a therapist can edit them per user.
5. Training and evaluation data come from healthy volunteers and public datasets. Patient data is out
   of scope for v1.

## Success targets (targets, not results)
These are the goals the project is evaluated against. Measured values appear only in reports
generated by the evaluation pipeline, in [10_model_card.md](10_model_card.md) and in the README results
table. Until they are measured, they read "NOT YET MEASURED".

| Metric | Target |
|---|---|
| Rep-count MAE per set | ≤ 0.5 |
| Shoulder angle MAE vs manual annotation | ≤ 8° |
| Elbow angle MAE vs manual annotation | ≤ 10° |
| Form-label macro-F1, subject-wise CV, own data | ≥ 0.85 |
| Server processing per landmark message (p95) | ≤ 10 ms |
| Temporal-model inference per window | ≤ 5 ms |
| Live client frame rate on Apple M3-class laptop | ≥ 20 FPS |
