# 10 — Model card

**No model in RehabPose has seen real data, and no model is enabled in the app.** Live sessions and
uploads use the rule engine. This card describes the temporal models the pipeline can train, and every
metric comes from generated skeletons. Format based on model cards for model reporting.

> RehabPose is a research and portfolio prototype. It is not a medical device, has not been
> clinically validated, and must not be used to diagnose, treat, or replace advice from a qualified
> healthcare professional. Stop exercising if you feel pain. Thresholds are engineering defaults, not
> clinical prescriptions.

## Model details
- **Version:** rehabpose 0.1.0, trained at commit `b48c5a1` with Python 3.12, torch 2.15.0 and the MPS
  device on one Apple M3 Pro.
- **Architectures:** LightGBM (`rep` only), TCN, LSTM, BiLSTM (`rep` only), Transformer and ST-GCN. See
  [06_ml_eval_plan.md](06_ml_eval_plan.md#3-models-rehabposemlmodels).
- **Input:** landmark and angle features for one arm from `rehabpose.core.features`, in 2D by default.
  `rep_*` uses one window per rep, resampled to a fixed length. `stream_*` uses causal sliding windows.
- **Output:** `rep_*` gives one form label per rep. `stream_*` gives a probability per compensation code
  per window.
- **Export:** ONNX and TorchScript bundles with parity checks. Bundles are git-ignored.
- **License:** Apache-2.0 for the code. No trained weights are distributed.

## Intended use
Research on camera-based form assessment, and demonstrating a reproducible evaluation pipeline. See
[09_ethics_privacy.md](09_ethics_privacy.md#2-intended-use-and-out-of-scope-use).

## Out-of-scope use
Any use with people, including feedback in a live session. Diagnosis, treatment or exercise-prescription
decisions, unsupervised clinical monitoring, and insurance, employment or legal decisions are all out of
scope, whatever future metrics show. See
[09_ethics_privacy.md](09_ethics_privacy.md#2-intended-use-and-out-of-scope-use).

## Training data
Generated by `rehabpose.synth`: 16 synthetic subjects performing scripted exercises with injected form
errors. No person was recorded. The same code defines the movements, the errors and the labels, so the
task is far easier than real data and the models may simply learn the generator.

## Evaluation data
Subjects S03, S04 and S12 from the same generator are held out for testing, and the rest form 5
subject-wise folds with 3 seeds. Public datasets and the project's own recordings have not been used.

What to read from these numbers:
- **The rule baseline is hard to beat here.** On the `rep` test sets the rule engine scores macro-F1 0.965.
  LightGBM is the only model above it, and the generator's errors were designed around the same rules.
- **Seed variation is large for some models.** `rep_transformer` ranges from 0.608 to 0.940.
- **Streaming flags rank well but threshold badly.** At the shared 0.5 threshold, `SHOULDER_HIKE` F1 is
  0.246 to 0.279 for seed 0, while its AUROC is 0.955 to 0.985. Per-code thresholds are not implemented.
- **ST-GCN is the weakest** on both tasks, and it has not been tuned further.

Ablations on generated data are in `reports/ablations/ablations-20261101-165706.md`, which is summarized
in the same JSON. Smoothing raised shoulder MAE from 0.77° to 2.26°, with rep-count MAE at 0.0 either way.
The likely cause is filter lag, which is unconfirmed.

## Subgroup results
NOT YET MEASURED. Synthetic subjects have no age, sex, skin tone, body type or ability attributes, so no
subgroup analysis is possible. The own-recording protocol logs lighting, clothing and posture, but not
yet any recordings.

## Limitations
- **Healthy-volunteer data only, at best.** Today there is no real data at all. The planned recordings
  are of healthy adults acting out errors, which differs from how patients actually compensate. Results
  would not transfer to patients without new evaluation.
- **View dependence.** A single camera cannot see depth reliably. Features are 2D by default, side-on
  views hide the far arm, and the owner reported poor side-view detection before later fixes. MediaPipe's
  side-on accuracy is NOT YET MEASURED.
- **Lighting.** Generated data has no lighting at all. Real effects on pose are NOT YET MEASURED.
- **Clothing.** Generated skeletons skip the image stage, so loose clothing that hides joints isn't
  represented. The effect is NOT YET MEASURED.
- **Body types.** Generated skeletons don't represent the real range of body shapes. MediaPipe's
  performance across body types, skin tones, ages, wheelchair users and people with limb differences
  was not evaluated here.
- **Clean input.** Training skeletons have simple noise rather than real pose-estimator errors.
- **Small test set.** Three test subjects give coarse confidence intervals.

More risks are in [04_exercise_spec.md](04_exercise_spec.md#11-known-limitations).

## Ethical considerations
- **False reassurance is the main risk.** A wrong "good form" cue could keep someone doing harmful
  movement, which is why no model is enabled and every report carries the disclaimer.
- **Unequal errors are possible and unmeasured.** Pose estimators can perform differently across
  groups, so subgroup results are required before any use with people.
- **Honest labelling.** Reports on generated data carry a SYNTHETIC banner, and these numbers must not be
  quoted as accuracy.
- **Privacy.** Video stays in the browser in live mode, and raw uploads are deleted after their job. See
  [09_ethics_privacy.md](09_ethics_privacy.md).

## How to reproduce
```bash
uv run rehabpose train --config configs/train/rep_tcn.yaml
uv run python scripts/summarize_results.py <commit>
```
`summarize_results.py` reads the git-ignored `reports/eval/` folder and takes the newest clean report per
config at the given commit. Absolute numbers may differ between machines and library versions.
